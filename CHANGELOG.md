# Changelog

## Development

- Added `internal/activate`, the server-side activator: the TRD 7.1 layout under a configurable root (`store/gen-<manifest id>`, `generations/<n>` and `current` relative symlinks, `secrets/<tool>`, `state.json`, `lock`/`lock.json`, `log/`), one exclusive `flock` per activate/rollback/gc that fails fast naming the holder, secret installation from a root-only payload (0600 files, payload deleted before anything is written), pull/`up -d --remove-orphans`/parallel per-tool health checks, `state.json` with a random nonce and deadline, confirmation by matching file, atomic `current` switch on confirm, and re-activation of the previous generation (or `docker compose down` when there is none) on health failure or deadline. Added `rollback` (same health-and-confirm protection) and `gc` (newest `keep` plus current, deleting only store entries no kept generation references, reporting freed bytes). Every Compose command is `docker compose -p olympus -f <file> …` from an argument list (A2, A11); health commands run with `docker compose exec` (A8). The Compose runner, health checker, clock and per-generation health source are interfaces, and 23 offline tests cover confirm, deadline, health failure, first-generation failure, the lock holder, stale nonces, rollback, gc retention, secret modes and secret-free logs and state. Recorded the activation contract in ADR 0027. Review then tightened four things: `gc` now aborts and deletes nothing when a kept generation cannot be resolved or its Compose file cannot be read, instead of collecting on a guess; a revert that cannot bring the previous generation back returns `RollbackFailedError` and records `rollback_failed` rather than claiming a rollback, so `RolledBackError` means the health checks actually passed; the secrets a tool had before an activation are copied to `secrets/<tool>.previous` and restored when the generation fails, deleted when it is confirmed, closing the previous gap where a failed generation kept the new values; and `Rollback` records the generation it tried to activate, not the one it returned to. The health spec lives in `internal/activate` for now because the manifest carries no health data: the follow-up is an optional `health` field on `generation.Tool` filled from `recipe.Health`. Secret fingerprints, `--force-recreate`, chown of secret files, failed-tool log capture, `bin/` cleanup in `gc` and all CLI/SSH wiring remain unimplemented.

- Added the Go offline core (`olym check` and `olym build`): strict positioned stack/recipe validation, local recipe rendering, deterministic YAML/TOML/JSON, confined tool files, localhost Compose ports, secret-free manifests and canonical hashes. Added a fictional MCP sample, golden/purity/confinement/secret-leak tests, embedded published schemas, development commands, and M1 progress evidence. Recorded approved parser dependencies in ADR 0020 and the offline artifact boundary in ADR 0021. Fixed PR #5 review findings: preserve integer types and large int64 precision through validation and all encoders, atomically replace manifest-owned build output after edits (ADR 0022), and propagate MCP serialization errors. Added integer, managed-seed, default rebuild, failed-staging and unrelated-output regression tests. Server commands, catalog fetching, image resolution and lock files remain unimplemented.

- Added the design-phase docs: product doc, design doc with architecture diagram, ADRs 0001–0012 in `docs/ADR.md`, user flows, stack file and recipe specs, apply edge cases, v1 plan, feature tracker, prototypes and landscape research.
- Added agent instructions (`AGENTS.md`, `CLAUDE.md`) and project skills in `.agents/skills/`: `ponytail`, `review-app-security` and `apply-security-fixes` (adapted with an AITerraform scope reference and rules A1–A12), and `aitf-test` (replaces the LRN QA skill).
- Decided the implementation model: Go (ADR 0013), local evaluation into generations with server-side activation and rollback (ADR 0014, supersedes 0011), one Docker Compose project as the runtime (ADR 0015), and the recipe set pinned as a flake-style input (ADR 0016, amends 0005 and 0008). Updated the design doc, product doc, specs, user flows, edge cases, glossary, v1 plan, tracker, AGENTS.md rule A11 and the aitf-test and security skills to match.
- Added ADR 0017 (server-side activation that rolls back unless the CLI confirms, from deploy-rs; amends 0014) and ADR 0018 (structured config built as data, published JSON Schemas, a cap on kept generations, from Helm; amends 0005). Added security rule A12 for the activator binary, Helm and deploy-rs notes in `docs/Sources/landscape.md`, and matching updates to the design doc, specs, edge cases, product doc, glossary, user flows, v1 plan, tracker and aitf-test skill.
- Added standalone `docs/PRD.md` (replaces `docs/product.md`) and `docs/TRD.md` (architecture, file formats, build and hashing, server layout, activation and rollback protocol, secrets, security rules, commands and exit codes, failure handling, testing, release). Aligned the stack-file spec with the TRD (JSON lock file, content-addressed generations) and updated links.
- Renamed the project from AITerraform to Olympus (ADR 0019): command `olym`, server paths `/var/lib/olympus/`, Compose project `olympus`, test skill `olympus-test`. Added planned distribution through an own Homebrew tap and the AUR to the PRD and TRD.
- Added `references/`: shallow clones of 11 reference repos (Terraform, OpenTofu, Nix, deploy-rs, Colmena, Helm, Docker Compose, Kamal, ClawHost, aideploy, Hermes Agent), listed in `references/repos.txt` and restored with `references/clone.sh`. The whole folder is git-ignored.
- Set the branch policy in `AGENTS.md`: `development` is the integration branch, and every change goes on its own branch and lands through a pull request into `development`.
- Added `docs/Sources/recipe-research.md`: recipe facts for the first three tools (Hermes Agent, Codex, OpenCode), checked against official docs, repositories and release notes on 2026-10-19 — image and tags, ports and health endpoints, data and config paths and formats, MCP configuration and secret delivery, skills, chat channels, authentication, runtime config writes, resources and licences — with the findings mapped onto the TRD section 16 open questions. Key findings: Codex has no official container image; all three tools rewrite their own config at runtime, so their config must be writable; Hermes chat channels are configured through environment variables, not a config key.
- Added the standalone `internal/catalog` and `internal/lock` packages: verified download, path-confined extraction and canonical hashing of the recipe catalog, strict byte-identical `stack.lock` read/write, and image tag to multi-architecture index digest resolution over the registry HTTP API. Offline tests cover determinism, tampering, path escape, lock round-trip and digest resolution. No dependencies added; decisions in ADR 0023 (catalog hash format) and 0024 (stdlib registry resolution).
- Added `internal/remote`, the SSH layer: key-file or agent connections with `known_hosts` verification (an unknown host goes to a confirm callback and is saved to `known_hosts` at mode 0600, a changed key is refused), argument-list commands with shell quoting and stdin, optional `sudo -n` wrapping, pure `/etc/os-release` detection for Ubuntu 22.04/24.04 and Debian 12, and Docker/Compose install steps (apt run with `DEBIAN_FRONTEND=noninteractive`) returned as argument lists. Added `golang.org/x/crypto v0.58.0`, which raises the module's minimum Go version to 1.26, and the `remote-ssh` feature record.
- Added the test lab (`lab/lab.sh`, ADR 0025): a disposable Ubuntu 24.04 VM under QEMU, booted from the verified cloud image with cloud-init, reachable only at `127.0.0.1:2222`, and resettable in about 15 seconds. It writes only to `.lab/` and needs only QEMU on the host.
- Fixed the test lab failing to restart: the cloud-init instance ID is now kept per disk (a new one regenerated the VM's SSH host keys), and `lab/lab.sh down` shuts the VM down cleanly through its ACPI power button instead of killing QEMU, which could lose freshly written host keys.
