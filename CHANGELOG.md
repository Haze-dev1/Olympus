- OLY-34: Corrected linker-set version, bundled both Linux activators in every CLI archive, fail closed when release checksums are missing, and pinned release actions to commit SHAs. Cross-compile release pipeline and activator checksum verification. - OLY-20: add a Gemini CLI recipe (`recipes/gemini-cli`) built on `node:22-bookworm-slim` with the pinned npm release `@google/gemini-cli@0.67.0`. MCP servers render into `/root/.gemini/settings.json` under `mcpServers` through the existing `hermes` style, which matches the documented stdio (`command`/`args`/`env` with `${VAR}`) and SSE (`url` + `headers`) shapes; streamable HTTP needs `httpUrl`, which no style emits, so it is recorded as a gap rather than worked around. `general.enableAutoUpdate` is disabled in the seeded template so the CLI cannot update past the pin, and the file is delivered through a `writable` init service so `/settings` can persist. Skills mount read-only at `/root/.gemini/skills`, `GEMINI_API_KEY` is the model-key secret, and `gemini --version` is the health check. Adds `testdata/gemini-cli` with a stack, a skill and the rendered generation as a fixture. No Go code changed; no live lab run (no QEMU on this host).

- OLY-56: added the `recipes/openbot` recipe for OpenBot (`ghcr.io/nightly-labs/openbot:0.62.0`, `linux/amd64` and `linux/arm64`), a self-hosted server for a local-first agent workspace. - OLY-55: recipes accept an optional `runtime` block and render it as fixed Compose keys instead of a passthrough. `shm_size` must parse as a positive size, `stop_grace_period` as a positive duration, `no_new_privileges: true` adds `security_opt: no-new-privileges:true`, and `seccomp` names a profile inside the recipe folder (rejected for URLs, absolute paths, traversal and recipes without a volume). The profile becomes a generated tool file at `<first volume>/.olympus/seccomp.json`, so it is hashed, uploaded under `/var/lib/olympus/store/<tool hash>/files/…`, shown by `plan` as a config change and passed to the daemon as `security_opt: seccomp=…`; the file is also bound read-only into the container. `no_new_privileges` stays opt-in rather than becoming a default for every tool. Schema validation now supports booleans. The lab was not run (no QEMU on this host). ADR 0045 records the decision. No dependencies added.
- OLY-31: `plan` and `apply` now run a read-only server preflight after SSH and privilege checks and before any mutation. It refuses an unsupported OS or CPU architecture, an image whose locked platforms lack `linux/<server arch>`, a declared port already in use (naming the process, and ignoring ports published by the current `olympus` generation) and less than 1 GiB free disk; it warns for less than 5 GiB free disk and for less memory than a recipe's `resources.min_ram`. Failures exit 1; warnings print after the plan diff and are covered by the normal apply confirmation. `check`/`update` now record sorted, de-duplicated image platforms in `stack.lock`, and `min_ram` must parse as a size such as `4GB` or `512MiB`. Offline fake-transport tests cover every check and sanitized remote text. Lab verification was not run (no QEMU on this host). ADR 0044 records the decision and amends ADR 0008; TRD 7.2, the failure table, recipe/lock specs and edge cases are updated. No dependencies added.
- OLY-30: selective secret recreation now cannot be skipped and survives a revert. `Recreate` is part of the activator's `Runner` interface instead of an optional type assertion, `Compose.Recreate` uses `--no-build --pull never --no-deps --force-recreate` like `Up`, an automatic revert recreates exactly the previous generation's tools whose secret files it restored (a tool that generation does not declare is skipped), and a failure to restore the previous secrets now takes the project down as well as reporting `rollback_failed`/exit 5 instead of leaving the failed generation running with the new values. Added offline regression tests, including red-before checks against the previous code. The lab verification was not run: this host has no QEMU. ADR 0043 amends 0027 and 0032.
