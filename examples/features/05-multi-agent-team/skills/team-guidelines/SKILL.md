# Team collaboration guidelines

1. Branch naming: use `feat/`, `fix/`, or `docs/` prefixes.
2. Code conventions: follow idiomatic language patterns and keep diffs minimal.
3. Testing: add table-driven unit tests for every new branch or error condition.
4. Security: never commit secrets, keys, or internal network paths.
